# Reads CARE makes by POST, sent with real bodies as every matrix role (P1-T11b3 review K3). The
# GET crawl never sees these answers and the write crawl sends an empty body with no query, so a
# regression in the search gate, the chart rule under search_retrieve, an accession lookup that
# ignores the place, or observation/analyse would pass every other matrix test. Each answer goes
# through the same checks as a GET answer: the outcome below, the canary and its exemptions
# (keys "POST <route> <label>"), the Owner rule and the key snapshot.
#
# <label> <route> [?<list_params.txt assignments>] <JSON body, no spaces> <who>:<outcome> ...  # why
#   body strings "@obj" / "@obj.attr" take the world object's id or attribute ("@obj.attr:5": its
#   first 5 characters); "@today" / "@today+6": a date. Outcomes and role groups as in
#   role_matrix.txt. Each route here has a role_matrix.txt POST row whose reason says "a read by
#   POST" (RoleMatrix.test_post_reads).

search-phone /api/v1/patient/search/ {"phone_number":"@patient.phone_number"}  all:allow owner,lab,store:deny  # the search gate (Q-K40): the front desk and the Radiologist (can_list_patients) get CARE's partial card (PatientPartialSpec: name, gender, year of birth, partial id; spec_exemptions.txt); the Owner, Lab Technician and Store Keeper are refused
