# The role x endpoint matrix (P1-T11b3; docs/reviews/p1-t11/design-b.md §6, "After the attack"
# §9 and §10 items 13-17). Reviewed: test_role_matrix.RoleMatrix requests every route of the
# hospital's URL configuration as every role below and compares each answer with this file. A
# route (or list_params.txt line) not here, or a row for no route, fails until it is reviewed.
# A restricted role reaching clinical data is a defect to fix in ihr_access, never a row.
#
# <methods> <route> [?<list_params.txt assignments>]  <who>:<outcome> ...  # why
#
# Who (later tokens win): all, ours (restricted + rad), restricted (rec cash tpa owner mrd lab
# store; registry.RESTRICTED), frontdesk (rec cash tpa mrd), billing (cash tpa), clinical (rad
# doctor admin), care (doctor admin), or roles: rec Receptionist, cash Cashier, tpa TPA Desk,
# owner Owner, mrd MRD (no records grant: P1-T11b4), lab Lab Technician, store Store Keeper,
# rad Radiologist, doctor Doctor (Paediatrics, CARE's), admin Facility Admin (CARE's). The
# Nurse who moved to the front desk keeping a PatientUser row is requested too and must answer
# exactly as rec.
#
# GET outcomes: allow (200 with rows, nothing projected), project (200 with rows, the guard
# projected a shape in it), empty (200, no rows), deny (401/403/404/405), invalid (400),
# conflict (409), unavailable (503), redirect (3xx), skip (not requested: fill() cannot fill
# it, or nothing here to show). Anything else, a 5xx above all, never matches.
#
# Writes: "W" is every non-GET method of the route; POST, PUT, PATCH, DELETE (comma-joined) name
# methods. A route with no write row: "ours:deny care:care". deny: sent with an empty JSON body
# as that role, and must not answer 2xx (or 5xx); where CARE validates the body before it
# authorizes, every role gets 400 there, so a deny row proves only that an empty write is not
# accepted (the grants themselves: ihr_roles ExactGrants). allow: not sent; the reason names
# the tests that cover the write ("tests: a.b.Class.test_x, ..."). care: CARE's own roles, not
# sent (no write crawl of CARE's roles). skip: fill() cannot fill the route, and only then: a
# skip row on a route fill() fills is requested (or sent) and fails (review M5). How each denied
# write answered is snapshotted in role_matrix_writes.txt (auth or body, review M3); an allowed
# write on a request, report or patient-scoped route names a test that sends it (review M4).
# Every GET route under a patient also has a "?encounter=encounter_b" row (another patient's
# visit, generated: matrix.CROSS, review K1/K2); reads by POST are in post_reads.txt (K3).
# GET rows were written from the answers (IHR_MATRIX_DUMP=1), each investigated before it
# was classified.
